# PRD：跨平台小说编辑器（NovelEditor）MVP

## 1. 需求背景（Requirement Background）

网络小说作者普遍进行长篇连载创作（单部作品 50 万\~500 万字），创作周期长达数年，核心痛点集中在三类：

1. **丢稿风险高**：码字软件崩溃、断电、误删导致稿件丢失，是网文作者最深恶痛绝的问题；
2. **长篇结构管理难**：数百上千个章节、多条人物线、复杂世界观设定，用 Word 等通用工具管理效率极低；
3. **多场景碎片化写作**：作者常在 PC 上码字、通勤途中用手机改稿或记灵感，缺乏可靠的跨设备同步方案。

对市面主流竞品调研结论如下：

| 竞品               | 核心功能亮点                           | 不足                        |
| ---------------- | -------------------------------- | ------------------------- |
| Scrivener（国际标杆）  | 活页夹章节结构、软木板卡片大纲、快照版本对比、字数目标、写作历史 | 无中文敏感词/排版、移动端弱、无 AI、上手门槛高 |
| 小黑屋              | 强制码字锁、码字速度统计、多级防丢稿、一键排版          | 云同步能力弱、界面老旧、无 AI          |
| 橙瓜码字             | 三端同步、素材库、码字统计、社群比赛               | 编辑体验一般、广告较多               |
| 壹写作              | 思维导图式大纲、角色管理、多端同步                | 大纲自由度高但章节管理弱              |
| 阅文作家助手           | 作品/章节管理、平台发布直连                   | 仅服务单平台、编辑器基础              |
| 彩云小梦 / Sudowrite | AI 续写、灵感生成                       | 仅 AI 场景，缺完整编辑器与稿件管理能力     |

**市场空隙**：目前尚无一款同时做到「专业长篇稿件管理 + 极致防丢稿 + 可靠三端同步 + 内置 AI 辅助」且面向中文网文作者的产品。本产品定位为填补该空隙的跨平台（Windows / Android / iOS）小说编辑器。

## 2. 目标与价值（Goals and Value）

**目标：**

- G1：提供支持「作品-卷-章」三级结构的稿件管理，单作品支持 1000+ 章节流畅操作（章节切换 ≤ 300ms）；

- G2：实现零丢稿：输入停顿 ≤ 2 秒自动保存，本地多副本备份 + 快照历史 + 崩溃恢复，三重保障；

- G3：实现 Windows / Android / iOS 三端云同步，断网可写，联网自动同步，冲突可解决；

- G4：提供 AI 续写、润色、灵感、角色卡生成四项核心 AI 能力，AI 结果均可被作者采纳、重试或忽略；

- G5：提供码字统计（当日/单章/全书字数、码字速度、写作历史），支持码字目标设定。

**价值：**

- 对作者：降低丢稿焦虑与长篇管理成本，碎片时间可写作，AI 提升产出效率与灵感获取速度；

- 对产品：以「防丢稿 + 三端同步 + AI」为差异化组合建立口碑，为后续增值服务打底座。

## 3. 术语与角色定义（Glossary）

- **作品（Book）**：一部小说，最高层级管理单元；

- **卷（Volume）**：作品下的分组，对应网文连载的"分卷"；

- **章节（Chapter）**：最小写作单元，即"一章"；

- **快照（Snapshot）**：章节某一时刻的完整文本副本，用于版本回溯；

- **素材卡**：角色卡、世界观设定、灵感便签等非正文的设定类内容；

- **强制码字模式**：锁定其他操作、仅允许输入的沉浸写作模式（参考小黑屋，MVP 简化版）；

- **角色**：唯一用户角色为「作者」，即使用本软件进行小说创作的人。

### 3.1 目标用户画像（Personas）

| 画像               | 特征                        | 核心诉求             | 高频场景            |
| ---------------- | ------------------------- | ---------------- | --------------- |
| **全职连载作者**       | 每日码字量大（3000\~1 万字），习惯固定设备 | 稳定可靠不丢稿、效率优先     | 长时间沉浸式码字、批量管理章节 |
| **通勤/碎片化作者**     | 上下班路上或间隙写作                | 三端流畅同步、移动端快捷记录灵感 | 手机短时写作、碎片时间记灵感  |
| **新人/创意型作者**     | 大纲敏感、依赖灵感与设定整理            | 结构引导、素材管理与回看     | 搭建世界观/角色卡、做大纲卡片 |
| **网文工作室统筹者**（辅助） | 管理多部书多章节                  | 快速定位章节、导出交付      | 全书字数统计、批量导出     |

> 说明：MVP 阶段仅「作者」一个正式用户角色；工作室统筹者暂按高级作者场景对待，不开放多账号协作。

### 3.2 典型使用场景（Scenarios）

- **S1 通勤碎片写作**：作者在地铁上打开手机端，续写昨天 PC 端留下的章节 → 输入停顿 2 秒自动保存 → 到公司后 PC 端自动拉取最新内容，两端内容一致；

- **S2 断网危机**：出差途中网络不稳，作者离线完成一章写作 → 联网后自动增量同步 → 若另一端也改过该章，弹出冲突界面；

- **S3 意外崩溃逃生**：写作中文档因系统重启异常退出 → 重新打开后自动恢复至最后一次保存点并提示 → 作者通过快照找回更早版本；

- **S4 AI 灵感卡壳**：剧情推进遇阻 → 用 AI 灵感生成剧情转折候选 → 存入灵感便签 → 稍后回看采用；

- **S5 平台投稿前整理**：全书完成后 → 一键排版 → 敏感词检测 → 导出 TXT/Word 提交平台。

## 4. 适用范围（Applicable Scope）

- **适用平台**：Windows 10+（x64）、Android 8.0+、iOS 13+；

- **适用用户**：中文网文作者（起点、晋江、番茄等平台连载作者及新手作者）；

- **适用范围**：本 PRD 覆盖 MVP 全部功能需求、关键流程与验收标准；

- **不适用**：出版排版、多作者协作、发布平台直连等场景（见第 5 节）。

## 5. 非目标（Non-Goals / Out of Scope）

- 不包含多作者协同编辑；

- 不包含发布平台（起点/晋江等）API 直连与一键发布；

- 不包含商业会员体系、支付、订阅（商业模式暂不考虑）；

- 不包含自研 AI 大模型，MVP 仅调用第三方大模型 API；

- 不包含 iPad/平板专属双栏布局优化（跟随通用布局）；

- 不包含 Web 端。

## 6. 功能需求（Functional Requirements）

### 6.1 编辑器核心

- **FR-1**：提供富文本编辑器，支持段落、加粗、斜体、标题（章内小标题）四种格式；网文正文以纯文本流为主，不做复杂排版；

- **FR-2**：自动保存——输入停顿 2 秒或每 30 秒触发一次落盘；保存失败必须以角标+弹窗提示用户；

- **FR-3**：支持撤销/重做（≥ 200 步），移动端支持系统原生手势；

- **FR-4**：提供沉浸写作模式（隐藏侧栏、全屏/软键盘优化）与夜间模式；

- **FR-5**：实时字数统计（单章字数、全书字数、本次会话新增字数），网文按"字符数（含标点）"口径计算，口径须在 UI 标注。

### 6.2 作品与章节管理

- **FR-6**：支持「作品-卷-章」三级结构；支持多作品；卷和章节支持新建、重命名、删除（删除进回收站，保留 30 天）；

- **FR-7**：支持章节拖拽排序（桌面端拖拽 / 移动端长按拖动）与置顶；

- **FR-8**：每章支持填写"本章大纲"（≤ 200 字），在大纲视图中以卡片形式展示并可拖拽调整章节顺序（参考 Scrivener 软木板）。

### 6.3 防丢稿

- **FR-9**：快照——每章支持手动快照与每日自动快照（保留最近 50 个），支持任意两版本差异对比与一键回滚；

- **FR-10**：本地多副本备份——稿件同时写入主存储与备份目录，备份保留最近 7 天；

- **FR-11**：崩溃恢复——应用异常退出后重新打开，自动检测并恢复至最后保存点，弹出恢复确认提示。

### 6.4 云同步

- **FR-12**：注册/登录（手机号或邮箱）后支持三端云同步；本地优先，联网时自动增量同步；

- **FR-13**：同一章节在多端均被修改产生冲突时，提供"保留我的 / 使用云端 / 两者都保留（生成副本）"三选一冲突解决界面，绝不静默覆盖。

### 6.5 码字统计

- **FR-14**：码字统计页展示日/周/月的码字字数、写作时长、码字速度（字/分钟）曲线；

- **FR-15**：支持设定每日码字目标（默认 2000 字），达成后以进度条+庆祝动画反馈。

### 6.6 AI 辅助

- **FR-16**：AI 续写——基于当前章节上下文（自动截取光标前 ≤ 3000 字）生成 1\~3 个候选续写片段，作者可插入、替换或忽略；

- **FR-17**：AI 润色——选中文本后可执行"润色 / 精简 / 扩写 / 对白优化"四类操作，结果以对照视图呈现，采纳后才写入正文；

- **FR-18**：AI 灵感——按类型（剧情转折、人物冲突、开脑洞）随机生成 3 条灵感条目，可一键存入灵感便签；

- **FR-19**：AI 角色卡——输入姓名与少量描述，自动生成角色卡（外貌、性格、背景、口头禅、人物关系），可编辑后保存至素材库；

- **FR-20**：所有 AI 功能须显示加载状态与失败重试入口；AI 生成内容不得直接自动写入正文（续写候选除外，需用户确认插入）。

### 6.7 素材库

- **FR-21**：素材库按作品组织，包含角色卡、世界观设定、灵感便签三类条目，支持新建、编辑、删除、搜索；

- **FR-22**：灵感便签支持桌面端全局快捷键快速唤起记录（Windows：Ctrl+Shift+N；移动端从通知栏/小组件快速进入，iOS 支持分享扩展收词）。

### 6.8 导入导出

- **FR-23**：导出——支持按章节/按卷/全书导出 TXT（可选是否含章节名）、全书导出 Word（.docx）；

- **FR-24**：导入——支持批量导入 TXT 自动按"第X章"规则切分为章节；支持导入 .docx 单文件为一个章节。

### 6.9 网文辅助（轻量）

- **FR-25**：一键排版——清除多余空行/空格、统一中文标点、段首缩进，操作前提供预览；

- **FR-26**：敏感词检测——内置可更新词库，检测到命中词时以黄色高亮标记并提供替换建议，不做强制屏蔽。

### 6.10 技术选型建议（供设计阶段决策）

- **客户端框架**：建议 Flutter（单代码库覆盖三端，自绘引擎对长文本滚动与编辑性能可控，社区有成熟文本编辑组件可参考）；备选 React Native（需重点验证长文档编辑性能）；

- **本地存储**：SQLite（章节正文建议以文件+元数据表混合存储，避免单章超长文本拖累查询）；

- **云同步**：自建增量同步服务（按章节粒度同步 + 版本号比对），或评估成熟 BaaS；

- **AI 能力**：统一 AI 网关层封装第三方大模型 API，Prompt 模板与服务端配置化管理，便于切换供应商。

### 6.11 需求优先级（MoSCoW）

MVP 版本按 P0/P1/P2 三级排定交付优先级，用于指导排期与验收裁剪：

| 优先级                      | 含义           | 功能范围                                                                                                                       |
| ------------------------ | ------------ | -------------------------------------------------------------------------------------------------------------------------- |
| **P0（必须有，MVP 上线底线）**     | 缺失则产品不可发布    | 编辑器核心（FR1-5）、作品/章节三级管理（FR6-8）、自动保存+快照+本地备份+崩溃恢复（FR9-11）、账号与三端云同步+冲突解决（FR12-13）、码字统计与目标（FR14-15）、基础导入导出（FR23-24）、一键排版（FR25） |
| **P1（应该有，MVP 后期或 V1.1）** | 显著提升体验，可小幅顺延 | AI 续写与润色（FR16-17）、灵感便签（FR18）、敏感词检测（FR26）、素材库（FR21）                                                                         |
| **P2（可以有，V1.2+）**        | 锦上添花，视资源决定   | AI 角色卡自动生成（FR19）、启发式灵感（FR18 增强）、全局快捷键/小组件/分享扩展（FR22）                                                                       |

> 注：AI 全量能力（FR16-19）统一作为增值项，MVP 首版至少交付「AI 续写+润色」中的一个以验证价值，其余按依赖 AI 网关就绪情况推进。

## 7. 非功能需求（Non-Functional Requirements）

### 7.1 性能

- **NFR-P1**：章节列表 ≥1000 项时，滚动与选中流畅（≥50fps）；章节打开到可编辑 ≤300ms；

- **NFR-P2**：单章 5 万字正文，输入延迟 ≤80ms，光标无感跟手；5 万\~10 万字仍可编辑，超长分章提示；

- **NFR-P3**：应用冷启动 ≤2s（桌面端 ≤2.5s）；自动保存单次落盘 ≤150ms；

- **NFR-P4**：AI 请求具有超时上限（建议 30s）与加载态，超时/失败可重试，不阻塞编辑器。

### 7.2 可靠性与数据安全

- **NFR-R1**：本地数据双副本（主存+备份），任一副本损坏可从另一副本或快照恢复；

- **NFR-R2**：自动保存采用"先写临时文件→原子替换"策略，避免写一半损坏主文；

- **NFR-R3**：同步冲突绝不静默覆盖，任何一端数据变更均有版本记录可查；

- **NFR-R4**：本地库与账号数据本地加密（桌面端可选、移动端默认），云端传输使用 TLS 加密；

- **NFR-R5**：删除的章节进回收站保留 30 天，过期自动清除前需再确认一次。

### 7.3 易用性与可访问性

- **NFR-U1**：桌面端主要操作提供快捷键，移动端提供手势；字数统计口径在界面显式标注；

- **NFR-U2**：夜间模式自动跟随系统或手动切换，字体大小可调，支持多档行距；

- **NFR-U3**：关键破坏性操作（删除卷/章、回滚、清空回收站）均有二次确认与撤销入口；

- **NFR-U4**：AI/AI 网关联不上时给出"降级为纯写作工具仍可用"的明确提示，不阻断本地写作。

> 未达成项的回退策略：云端不可用时，本地写作全部可离线完成，仅同步功能暂缓并明显提示。

## 8. 核心数据模型（Core Data Model）

> 供设计阶段对齐字段，MVP 以 SQLite 本地表 + 服务端镜像为准；字段可增补但不得破坏以下主键/外键关系。

- **User（用户）**：id、手机号/邮箱（登录标识）、昵称、头像、注册时间、设备令牌列表；

- **Book（作品）**：id、userId、书名、作者笔名、简介、封面、创建/更新时间、删除标记（软删）；

- **Volume（卷）**：id、bookId、卷名、排序号、创建/更新时间；

- **Chapter（章节）**：id、bookId、volumeId、标题、正文（文件引用或 TEXT）、本章大纲、排序号、当前版本号、字数(字符数)、最后编辑时间、光标位置（恢复用）；

- **Snapshot（快照）**：id、chapterId、版本快照正文、生成时间、类型(手动/自动/回滚前)、保留标记；

- **BackupFile（备份）**：id、bookId，文件路径或 blob、备份时间；过期按 7 天清理；

- **RecycleBin（回收站）**：id、type(卷/章/素材)、originId、原路径、删除时间、过期时间(30 天)；

- **Note（素材：角色卡/世界观/灵感便签）**：id、bookId、类型、标题、正文、标签、创建/更新时间；

- **WriteRecord（写作记录）**：id、userId、日期、本次会话新增字符数、写作时长；

- **SensitiveConf（本地敏感词偏好）**：词库版本、开关、命中词替换建议缓存。

关键关系：`User 1—N Book 1—N Volume 1—N Chapter`；`Chapter 1—N Snapshot`；`Book 1—N Note`（素材可跨卷归属 book 层）。

## 9. 交互与页面结构概览（UX / IA Map）

> 用于统一三端信息架构；同一功能在三端以相同层级呈现，交互从桌面端派生、移动端适配。

- **9.1 书架页（首页）**：作品列表（卡片/列表）、新建作品、回收站入口、设置、账号；

- **9.2 作品工作区**：左=作品树（卷/章，拖拽排序）；中=大纲卡片视图（可切换）；右=正文编辑器（沉浸模式隐藏左右栏）；

- **9.3 编辑器工具栏**：段落/标题/加粗/斜体、字数统计、AI 入口、保存状态（含失败角标）、导入导出、排版、敏感词检测；

- **9.4 AI 面板**：续写/润色/灵感/角色卡四类；候选卡片、加载态、失败重试、采纳后不自动落正文；

- **9.5 快照/历史**：章节级快照列表、两版本对照、回滚、回滚前自动建快照；

- **9.6 码字统计页**：日/周/月导数字、时长、速度曲线、每日目标进度条；

- **9.7 素材库页**：分类 Tab（角色卡/世界观/灵感便签）、新建/编辑/搜索/删除；

- **9.8 设置页**：同步开关、导入导出、自动保存频率、夜间模式、字体与行距、敏感词词库更新、关于。

> 页面冷启动默认落地：桌面端=书架页（恢复上次定位到章节）；移动端=书架页或上次编辑章节（可配置）。

- **商业化潜力（后续）**：付费意愿调研；订阅转化率（V1.3 之后参考）。

## 12. 关键流程（Key Flows）

### 12.1 新建作品并写作

1. 用户点击「新建作品」→ 输入书名 → 系统创建默认「第一卷 / 第一章」；
2. 用户在编辑器输入正文 → 停顿 2 秒自动保存 → 字数统计实时更新；
3. 关闭应用 → 下次打开自动定位到上次编辑章节与光标位置。

### 12.2 多端同步

1. 设备 A 写作产生章节变更 → 本地落盘并记录版本号 → 联网时推送云端；
2. 设备 B 打开 → 拉取增量更新 → 合并到本地；
3. 若检测到冲突 → 弹出冲突解决界面（保留我的 / 使用云端 / 两者都保留）→ 用户选择后完成同步。

### 12.3 AI 续写

1. 用户将光标置于段落后 → 点击 AI 续写按钮 → 显示加载动画；
2. AI 网关返回 1\~3 个候选片段 → 以卡片浮层展示；
3. 用户点选其一 → 预览插入效果 → 确认插入正文（可撤销）或点"换一批"重试或关闭浮层。

### 12.4 历史版本回滚

1. 用户进入章节 → 打开「历史快照」列表 → 选择某快照；
2. 点击「对比」查看与当前版本的差异 → 点击「回滚」；
3. 系统先将当前版本自动存为快照，再执行回滚，保证操作本身可逆。

## 13. 风险与依赖（Risks and Dependencies）

**风险：**

- R1：Flutter 长文档（单章 5 万字+）编辑性能与中文输入法组合输入（IME）兼容性需尽早技术验证，存在选型返工风险；

- R2：多端同步冲突策略若不完善，可能造成用户感知"丢稿"，品牌伤害极大，冲突处理必须"宁可冗余不可覆盖"；

- R3：依赖第三方大模型 API，存在服务质量、内容安全合规与成本波动风险；AI 生成内容需接入内容安全审核；

- R4：移动端后台限制可能中断自动备份，需设计前台保存优先策略。

**依赖：**

- D1：云同步服务端（账号体系、增量同步 API）；

- D2：第三方大模型 API 及其内容安全审核服务；

- D3：敏感词词库的持续更新来源；

- D4：三端应用商店（Windows 可选官网分发）的审核与上架流程。

## 14. 验收标准（Acceptance Criteria）

- [ ] 三端均可完成「新建作品 → 新建章节 → 写作 → 保存」全流程；

- [ ] 输入停顿 ≤ 2 秒内容自动落盘；强杀进程后重开，最后保存内容不丢失且触发恢复提示；

- [ ] 单作品导入/创建 1000 个章节时，章节列表滚动与切换无明显卡顿（章节打开 ≤ 300ms）；

- [ ] 快照可创建、对比、回滚，且回滚前自动生成当前版本快照；

- [ ] 两端修改同一章节触发冲突界面，三个选项行为正确，无静默覆盖；

- [ ] 断网状态下可正常写作，联网后自动完成增量同步；

- [ ] 字数统计口径为"字符数（含标点）"，单章/全书/会话三项数据准确（与手工统计一致）；

- [ ] AI 续写可返回候选、可插入、可撤销、可重试；AI 失败时有明确错误提示与重试入口；

- [ ] AI 润色/灵感/角色卡结果均不自动写入正文或素材库，需用户确认；

- [ ] 导出 TXT（含/不含章节名）与 Word 格式可被常规阅读器/Word 正常打开；

- [ ] 批量导入 TXT 可按"第X章"正确切分章节；

- [ ] 一键排版预览可见且应用后可撤销；敏感词命中以高亮呈现；

- [ ] 三端均通过各自平台审核要求上架（或具备官网分发包）。
